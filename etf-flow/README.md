## 净申赎怎么算

```
净申赎金额 = (当日份额 − 前一披露日份额) × 当日单位净值
```

单位是亿元。正数是净申购（红色），负数是净赎回（绿色）。

份额用交易所披露的场内规模，净值用基金公司公布的单位净值，不用收盘价代替净值。没有前一日份额的新基金，第一天不记成申购。份额变成 0 的打印当成缺失，不当成全部赎回。前一披露日隔了超过 15 个自然日，也不把这段缺口当成赎回。

份额折算：净值单日变动达到 15%，或者变动达到 8% 且份额×净值基本不变时，先把前日份额换算到当日净值上，再算差额。纯折算的净申赎接近 0。

净值偶尔晚一天。缺净值时最多沿用 5 个自然日内的上一笔净值。

## 七类覆盖

名单不是手写代码。东方财富 `RPT_FUND_ETF_INDEX` 给每只场内 ETF 标了跟踪指数，指数代码落在下面这七个里就计入。指数增强如果跟踪的是同一个代码，也算进去。2026-10-23 的合计要带上增强，才和截图上的 `+510.82` 对得上。

东财名单里有、但当天交易所没披露份额的基金不进合计。快照的 `coverage` 写了名单只数和当天有份额的只数。

## 规模和折溢价

```
规模     = 份额 × 单位净值
折溢价率 = (收盘价 − 单位净值) / 单位净值
```

规模含行情涨跌。某一天的规模变化，大约等于净申赎加上价格涨跌，页面在「总规模」里把这两项分开。

折溢价用新浪不复权日收盘，不是盘中 IOPV。免费日频里没有可靠的历史 IOPV，所以这一页是收盘口径。类别折溢价按规模加权。当天没有收盘的基金不进加权。

今年以来从 2026-01-05 到 2026-10-23 共 **193** 个交易日，日均合计 **-66.95 亿元**（快照里的 `coverage.ytd_mean_total`）。同一天的小程序图上写的是 -66.99，差 0.04 亿元，来自个别日期的净值沿用和份额折算；单日合计和近一月分项与截图对齐。

## 时间窗口

- 近五日：最近 5 个交易日
- 近一月：快照日往前 1 个日历月，含两端。快照 2026-10-23 时是 2026-09-23 至 2026-10-23
- 近三月：同样往前 3 个日历月
- 今年以来：当年 1 月 1 日至快照日

申赎表默认近一月。净申赎合计的柱状图默认今年以来，零轴在中间，红色向右、绿色向左。

## 数据从哪来

不需要 API key。脚本只用 Python 3 标准库。

| 用途 | 来源 |
|------|------|
| 跟踪指数 | 东方财富 datacenter `RPT_FUND_ETF_INDEX` |
| 上交所份额 | `query.sse.com.cn` `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L`，`TOT_VOL` 是万份，乘以 10000 |
| 深交所份额 | `www.szse.cn` ShowReport `CATALOGID=scsj_fund_jjgm`，xlsx 里的「基金规模(份)」 |
| 单位净值 | 新浪 `CaihuiFundInfoService.getNav` |
| 收盘价 | 新浪 `CN_MarketData.getKLineData`，不复权 |

某一天披露到的基金数明显少于这段时期的中位数（不到 72%）时，这一天不进表，避免只到了一边交易所时看起来像大额赎回。快照日有份额的基金少于 120 只时，脚本拒绝覆盖已有快照。

`data/history/funds.json` 存每只基金的份额、净值和收盘，供下一次增量更新。页面不读这个文件。

## 本地运行

在仓库根目录：

```bash
python3 etf-flow/scripts/test_etf_flow.py
python3 etf-flow/scripts/fetch_etf_flow.py
python3 -m http.server 8741
```

打开 http://127.0.0.1:8741/etf-flow/ 。全量重拉（忽略已有库存）：

```bash
python3 etf-flow/scripts/fetch_etf_flow.py --rebuild
```

## 更新频率

`.github/workflows/update-etf-flow.yml`

- 定时：`0 11 * * 1-5`（UTC）= 北京时间周一至周五 19:00。比 16:00 的基差任务晚，是因为交易所份额文件多在收盘后傍晚才齐，深交所也注明早间修订为准。
- 每次重读最近约 8 个自然日，用来吃进次日早间的修订。周五晚间的数字，下周一 19:00 会再对一次。
- 也可在 Actions 页手动 `workflow_dispatch`
- 与股指、商品、AH、期现、期权成交量共用并发组 `update-basis`，提交前 `git pull --rebase`
- 只提交 `etf-flow/data`
